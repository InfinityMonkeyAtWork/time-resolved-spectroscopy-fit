## API contract & ownership

- [1] **Settle the public-API and ownership contract** (a design doc in `docs/design/`): supported access, supported mutation, and ownership defined together, covering returned objects and attributes taught in examples, not just top-level exports. File raw data and axes are construction-only owned inputs (replacing them means a new `File`); a File's primary axis may be time, not only energy, so guards validate the primary axis rather than hard-coding energy (the time-trace feature itself stays at step 13); corrections are explicit operations that recompute from raw data and owned dark/calibration arrays; baselines come only through the baseline API; authored models change through YAML and reload, with attachments captured declaratively; fit seeds, fitted values, sweep values, and ML predictions are explicit execution state that never rewrites the definition or past results; completed results are protected snapshots; `File.describe()` and model previews legitimately use current state. Choose the parameter vocabulary here (implemented in step 5). Does not wait for an inventory of every helper; steps 2 and 6 can start alongside (2026-09-24).
- [4] **Decide how to guard/warn against in-place mutation of user-facing arrays**: internal machinery assumes `File.data`/`energy`/`time` and fit outputs are stable once set — e.g. `SavedFitSlot` originally stored `params`/`observed`/`fit`/`selection` by reference (2026-07 code review, check 1; resolved — the schema-7 capture copies and freezes its arrays, see the 2026-07-28 note below), and file version stamps / `fit_view_sha256` are computed once at slot capture. A user mutating `file.data` in place instead of re-instantiating would desynchronize slots, fit limits, and cached evaluations in ways no single defensive copy fixes — so slot-level copies were considered and declined (2026-07-10) as papering over one symptom. Decide on a systemic stance instead: read-only views (`setflags(write=False)`) on public arrays, copy-on-set in setters, a documented ownership contract, and/or re-hash validation at save time. A sibling case, resolved 2026-09-22 (sigma-weighting): `Simulator.sigma_data` and `noise_model` are snapshots taken when the noise is drawn, so `set_noise_level`/`set_noise_type` after `simulate()` no longer change what `save_data()` and the sweep persist. Note (2026-07-28): the schema-7 archive deliberately does **not** depend on this being resolved — it copies and freezes its own arrays at capture as an ownership boundary, so `SavedFile` / `SavedFitSlot` stop holding references into live `File` state. Making this a prerequisite was considered and rejected (four unresolved candidate mechanisms; blocking a wire format on a systemic redesign trades one open problem for another). The item stays worthwhile on its own merits for the live-API question — what happens when a user mutates `file.data` and then plots or refits. Update (2026-09-02): the post-first-fit half is answered — a `data_raw`/axis mutation raises at the next fit (capture-hash guard) and completed-fit rendering is insulated (captured `SavedFile` providers). Remaining scope: the never-fitted/pre-fit surface (mutations desync fit limits, `data_base`, propagated model axes with no guard), and in-place mutation of the derived `data` view — the stamp hashes `data_raw` + corrections, not `data`, so a mutated-`data` refit mints the *same* handle and surfaces only later as a divergent-values collision at save. Hand-assigning `data_base` (bypassing `define_baseline()`) is part of that pre-fit surface and will no longer be allowed once ownership lands: `define_baseline()` becomes the only source of the baseline, the four tests that assign `data_base` directly get rewritten, and the `fit_baseline` guard that refuses declared noise on a hand-set baseline (added 2026-09-21, sigma-weighting) is removed with it.
- [4] **Make model edits atomic and protect returned result contents**: the September 2026 review reproduced that reloading removes the existing model before its replacement has loaded and that a rejected dynamics attachment can leave parameter state changed — construct and validate the candidate before publishing it, so a failed replacement or attachment leaves the previous model usable. Public result records expose mutable DataFrames and dictionaries inside frozen dataclasses; return protected views or detached copies so editing a returned table cannot change a recorded fit or its archive. Own the correction arrays (`dark`, `calibration` are stored by reference today) as copies. Regression coverage for the caller-mutation, returned-result-mutation, and failed-edit cases, driven by the behavioral probes of step 3. Keep the correction/noise restrictions until σ propagation lands (step 13). Check that simulator-generated arrays stay associated with the parameter state and definition that produced them (2026-09-24).

## Noise and simulation

- [13] **Noise estimation helpers**: `File.set_noise` takes the noise as given (`scale` from the count budget or `Simulator.noise_model`, σ from a known detector); add estimators for the two common cases — the temporal RMS of a static block for a Gaussian σ (notebook 13 does it by hand) and a photon-transfer `scale` from variance versus mean over a static block for counting data — as helpers that return `set_noise` kwargs, not as automatic detection.
- [13] **Compound counting likelihood**: analog detectors with an excess-noise factor and read noise are neither pure Poisson nor uniform Gaussian; a Poisson + Gaussian read-noise residual (or the excess-noise-reduced count that `sensitivity` already documents) would let `set_noise` describe them. Per-point Gaussian σ covers the linearized case today.
- [13] **Propagate σ through corrections**: `subtract_dark` / `calibrate_data` / `reset_*` raise under a declared weighted model because σ describes the uncorrected view and nothing is propagated (2026-09-21). Propagating a per-point σ (dark: add variances; calibration: scale) would let the declaration survive corrections; needs the array-ownership stance (step 4) first.
- [13] **Declare noise in the fit-mechanics notebooks**: 01/02/03/04/20/21 fit counting data under the `unknown` default by design (they teach fit mechanics; 12/13 own uncertainty, decided 2026-09-22), so their printed `stderr` are the unweighted default and 01 says so. Revisit once uncertainties enter those notebooks, and let the per-point σ path weight the SbS-derived trace fit (item above) when that lands.
