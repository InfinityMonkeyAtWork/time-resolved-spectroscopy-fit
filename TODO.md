# Project TODOs

## Fitting

- [ ] **Enable 1D time-trace fitting (post-SbS kinetics)**: wire standalone `TIME_1D` dynamics models (already evaluable on the mcp path per `docs/design/supported_models.md`, but connected to no fit method) to a fit entry point, so parameter-vs-time traces extracted from SbS results can be fit to `functions/time.py` dynamics (`expFun` sums, IRF convolution) inside the package instead of in external scripts. Frame it as the diagnostic/initialization rung before `fit_2d`, not a statistical equivalent (per-slice correlations and unpropagated SbS uncertainties make two-step inferior). Design direction: promote SbS results into a time-axis `File` — the promoted object inherits limits/CI/MCMC/save/export machinery, and trace fits land in a `SavedFitSlot` like every other fit type (no parallel fitting pipeline). Requires `File` to support time as the primary axis, which today it assumes is energy. Weighting traces by per-slice stderr ties into the `sigma_type` expansion item below — the per-slice stderr itself is persisted since v0.14.0 (`SavedFitSlot.params_stderr`).

## Fit archive & result identity

- [ ] **Validate project, file, and model names as path segments**: `Project.name`, `File.name` and model names are guarded identity (Principle 1) and appear verbatim in paths — the archive default `./fit_results/<project>.fit.h5` and the export tree `<root>/files/<file>/<model>/<handle8>/` — yet nothing validates them today (a derived `File.name` is `Path(path).stem`). A name with `/` or `\\`, `.` / `..`, a trailing dot or space (stripped on Windows), a Windows-forbidden character or device name (`< > : " | ? *`, `CON`, `NUL`, …), or a case-only twin of another name (case-insensitive filesystems on Windows and macOS) nests, escapes, strips or merges directories depending on the OS. Decide the rule at construction time, where the identity contract lives, not by sanitizing at export (a sanitizer maps distinct names onto one directory and hides the identity). Inner dots stay legal (`run.001`). No names need reserving: the export tree keeps every user-named segment under a fixed `files/` or `joint/` node (2026-09-20), and an export-time refusal was rejected because names are immutable, so the user would have no remedy. Breaking for names that violate the rule; land before v1.0 (2026-09-20).

## Noise and simulation

- [ ] **Noise estimation helpers**: `File.set_noise` takes the noise as given (`scale` from the count budget or `Simulator.noise_model`, σ from a known detector); add estimators for the two common cases — the temporal RMS of a static block for a Gaussian σ (notebook 13 does it by hand) and a photon-transfer `scale` from variance versus mean over a static block for counting data — as helpers that return `set_noise` kwargs, not as automatic detection.
- [ ] **Compound counting likelihood**: analog detectors with an excess-noise factor and read noise are neither pure Poisson nor uniform Gaussian; a Poisson + Gaussian read-noise residual (or the excess-noise-reduced count that `sensitivity` already documents) would let `set_noise` describe them. Per-point Gaussian σ covers the linearized case today.
- [ ] **Propagate σ through corrections**: `subtract_dark` / `calibrate_data` / `reset_*` raise under a declared weighted model because σ describes the uncorrected view and nothing is propagated (2026-09-21). Propagating a per-point σ (dark: add variances; calibration: scale) would let the declaration survive corrections; needs the array-ownership stance below first.
- [ ] **Declare noise in the fit-mechanics notebooks**: 01/02/03/04/20/21 fit counting data under the `unknown` default by design (they teach fit mechanics; 12/13 own uncertainty, decided 2026-09-22), so their printed `stderr` are the unweighted default and 01 says so. Revisit once uncertainties enter those notebooks, and let the per-point σ path weight the SbS-derived trace fit (item above) when that lands.

## Performance & architecture

- [ ] **JAX backend follow-ons**: the backend itself shipped in v0.12.0 (Phases A–D of [docs/design/archive/jax-planning.md](docs/design/archive/jax-planning.md); execution record in [docs/design/archive/jax-backend.md](docs/design/archive/jax-backend.md)). Remaining candidates, none scheduled:
  - Full-parameter-vector evaluator variant for interactive use (fixed-value edits without recompile) plus session-level evaluator caching — see [docs/design/ui.md](docs/design/ui.md).
  - vmap-batched slice-by-slice solver (the one workload where lmfit overhead plausibly dominates; would be the Phase E pilot) — see [docs/design/ui.md](docs/design/ui.md).
  - `vmap`-batch homogeneous file series in the fused project fit: unrolled per-file fusion shipped in v0.13.0 and compiles a ten-file program in a few seconds (see [docs/design/project-level-fits.md](docs/design/project-level-fits.md)); batching identical-grid files through one evaluator body is the follow-on if compile time ever becomes a complaint (moved here 2026-09-17).
  - `fit_model_compare`-style runtime JAX parity mode, or a cheaper one-shot pre-fit parity check on the JAX path.
- [ ] **Decide how to guard/warn against in-place mutation of user-facing arrays**: internal machinery assumes `File.data`/`energy`/`time` and fit outputs are stable once set — e.g. `SavedFitSlot` originally stored `params`/`observed`/`fit`/`selection` by reference (2026-07 code review, check 1; resolved — the schema-7 capture copies and freezes its arrays, see the 2026-07-28 note below), and file version stamps / `fit_view_sha256` are computed once at slot capture. A user mutating `file.data` in place instead of re-instantiating would desynchronize slots, fit limits, and cached evaluations in ways no single defensive copy fixes — so slot-level copies were considered and declined (2026-07-10) as papering over one symptom. Decide on a systemic stance instead: read-only views (`setflags(write=False)`) on public arrays, copy-on-set in setters, a documented ownership contract, and/or re-hash validation at save time. A sibling case, resolved 2026-09-22 (sigma-weighting): `Simulator.sigma_data` and `noise_model` are snapshots taken when the noise is drawn, so `set_noise_level`/`set_noise_type` after `simulate()` no longer change what `save_data()` and the sweep persist. Note (2026-07-28): the schema-7 archive deliberately does **not** depend on this being resolved — it copies and freezes its own arrays at capture as an ownership boundary, so `SavedFile` / `SavedFitSlot` stop holding references into live `File` state. Making this a prerequisite was considered and rejected (four unresolved candidate mechanisms; blocking a wire format on a systemic redesign trades one open problem for another). The item stays worthwhile on its own merits for the live-API question — what happens when a user mutates `file.data` and then plots or refits. Update (2026-09-02): the post-first-fit half is answered — a `data_raw`/axis mutation raises at the next fit (capture-hash guard) and completed-fit rendering is insulated (captured `SavedFile` providers). Remaining scope: the never-fitted/pre-fit surface (mutations desync fit limits, `data_base`, propagated model axes with no guard), and in-place mutation of the derived `data` view — the stamp hashes `data_raw` + corrections, not `data`, so a mutated-`data` refit mints the *same* handle and surfaces only later as a divergent-values collision at save. Hand-assigning `data_base` (bypassing `define_baseline()`) is part of that pre-fit surface and will no longer be allowed once ownership lands: `define_baseline()` becomes the only source of the baseline, the four tests that assign `data_base` directly get rewritten, and the `fit_baseline` guard that refuses declared noise on a hand-set baseline (added 2026-09-21, sigma-weighting) is removed with it.

## Road to v1.0.0 & first adopters

Rationale (2026-07-06): lock-in comes from schemas and public names, not from users — so stabilize the contract surfaces (1–4) before the website (5) and outreach (tracked outside the repo: `~/Desktop/trspecfit_outreach.md`). Early TR-XPS/TR-XAS adopters are then a feature, not a risk: they supply the usage signal that feature decisions currently lack, and their needs are a strict subset of the general "parameterized lineshapes vs. control axis" problem, so serving them does not distort the architecture.

1. [ ] **Version the model-definition schema and close the simulate → predict → rehydrate loop**: model YAML files are the artifact user groups accumulate, and currently the only unversioned contract — the fit archive already carries `SCHEMA_VERSION` ([fit_io.py](src/trspecfit/utils/fit_io.py) ~L46) and refuses mismatched reads/appends. Add an optional top-level format-version key in `utils/parsing.py` (absent = current version) so future syntax changes can warn or migrate instead of silently misparsing old model files. Since schema 7 the per-slot `model_yaml/` records (`ModelYamlRecord`: role, name, source file, target parameter, sequence index, verbatim text — one per energy model, dynamics and profile attachment, built from a bare `Model` via `yaml_provenance()`) already are that model-definition record, so treat the versioned schema and the records as one contract. Three additions make a dataset self-describing for ML / inverse-problem work (2026-09-17): (a) `Simulator.save_data` and the sweep output write the same records once per file next to the per-configuration `model_parameters` values, so a training set states which model produced it, and carry the noise declaration (`noise_type` / `noise_scale`, the `Simulator.noise_model` kwargs; deferred here from the sigma-weighting work 2026-09-22 so no field lands in the pre-compliance layout — until then it is derivable from the stored detection metadata and `clean_data`); (b) `model_structure` gains profile attachments (dynamics only today), completing the canonical index an ML target spec consumes; (c) a rehydration helper rebuilds a live `Model` from the records without the original YAML files — first version writes each record's verbatim text to a temporary YAML and replays `load_model` plus the attachments from `name` / `target_par` / `sequence_index`; a from-text parser entry point is the clean follow-up (`load_model` and `utils/parsing.py` are path-based). Within a session the loop closes on the live truth model; the helper is what lets another process evaluate a prediction by simulating from it.
2. [ ] **Curate the public API surface**: audit user-facing classes (`File`, `Project`, `Simulator`, `Model`, etc.) and decide which methods/attributes should be discoverable in notebooks and docs. Add curated `__dir__()` output for autocomplete, keep `__all__`/API docs aligned, and gradually rename or deprecate internal helper methods that should not look like primary user workflows. This should improve both human notebook ergonomics and AI/LLM efficiency by making the intended workflow surface smaller, clearer, and easier to infer. Prerequisite for outreach: once external groups have notebooks, every public-looking name is frozen in practice.
3. [ ] **Document API tiers**: add a short guide that separates stable user API (`Project`, `File`, `Simulator`, `PlotConfig`), advanced public API (`mcp.Model`, `Component`, `Par`, `ParameterSweep`, `MC`), and internal implementation modules (`graph_ir`, `eval_1d`, `eval_2d`, low-level parsing/HDF5 helpers). Use this as the source of truth for docs, tests, examples, and AI-agent guidance. Also settles which surfaces get the post-1.0 deprecation commitment — `docs/stability.md` (2026-07-12) commits the user API and explicitly defers the advanced tier to this guide. Reconcile the agent-facing orientation docs (`llms.txt`, `AGENTS.md`) against the finalized tiers in the same pass — they restate API/knob details (e.g. the headless `show_output`/`auto_export` guidance) that silently drift from the code otherwise.
4. [ ] **Remove legacy/backwards-compat code**: audit codebase for legacy fallbacks and backwards-compatibility shims and consider removing before v1.0.0. The big blocker cleared in v0.14.0 (`save_sbs_fit` / `save_2d_fit` and the `_save_*_fit_legacy` impls are gone; auto-export routes through the slot exporter). Known shims still slated for removal:
   - Legacy pre-rename format branch in [sweep.py](src/trspecfit/utils/sweep.py) ~L624 and the legacy `save_img` int-mapping helper in [plot.py](src/trspecfit/utils/plot.py) ~L813.
   - The `time_unit` argument of `Dynamics.normalize_time` in [mcp.py](src/trspecfit/mcp.py) ~L2711: a power-of-ten scale its own docstring calls "currently unused" and nothing passes; `frequency` is in reciprocal time-axis units and the examples now say so (2026-09-15).
5. [ ] **`trspec.fit` project website**: stand up the site as the home for fully rendered example notebooks (plots, fit tables) so users can browse without installing — preferred over Read the Docs, which has build timeouts/execution limits for notebooks. Room to grow into interactive tooling: a model-builder UI (GUI that outputs the YAML model files) and other future work. Keep git notebook sources stripped (`nbstripout`); render/execute at publish time so outputs never drift from the code.
